# Мультислой

**Автор:** Горшков Сергей Владимирович  
**Сайт:** https://nookbat.ru

Локальное приложение для тестирования операционных систем и программ в виртуальных машинах **QEMU**. В Linux используется ускорение **KVM**, в Windows — **WHPX**. Без аппаратного ускорения можно явно выбрать более медленную эмуляцию **TCG**. Управление — нативный русский GUI на Qt и CLI. Нет веб-сервера, облачного аккаунта или замены основной ОС.

## Возможности версии 0.1

- Создание ВМ x86-64, настройка RAM/CPU, отдельные разреженные диски QCOW2.
- Установка с ISO через виртуальный DVD, отдельный DVD с драйверами, порядок загрузки.
- BIOS/UEFI, Secure Boot с подходящей прошивкой, постоянное состояние TPM 2.0 через swtpm на Linux.
- Запуск, штатное выключение гостя, принудительная остановка, пауза, продолжение, перезагрузка через QMP.
- Окно консоли QEMU с клавиатурой и мышью. Закрытие менеджера не выключает ВМ; повторный запуск менеджера восстанавливает управление.
- Изменение параметров выключенной ВМ, независимое клонирование, офлайн-снимки диска с состоянием UEFI/TPM и настройками ВМ.
- Включение/отключение виртуального сетевого кабеля на работающей ВМ.
- Перенос выбранной папки с хоста в гостя через автоматически создаваемый **DVD только для чтения**. Unicode-имена поддерживаются через Joliet/Rock Ridge. Обновляется при запуске ВМ; ссылки не копируются, лимит 8 ГБ, имя файла до 64 символов. Это не двусторонняя живая общая папка.
- AppImage с меню установки/обновления/удаления, DEB-пакет и EXE-установщик. Обновление/удаление приложения сохраняет ВМ.

Это первая версия менеджера, **не полный аналог Proxmox**: нет кластера, миграции, управления физическими мостами/VLAN, PCI/USB passthrough, онлайн-снимков памяти, увеличения диска или резервного копирования.

## Гостевые и основные ОС

Целевые **гостевые** ОС x86-64: Debian, Ubuntu, Arch Linux, Astra Linux, РЕД ОС, FreeBSD, CentOS/CentOS Stream и похожие системы; Windows 10 и Windows 11. Совместимость конкретной версии зависит от ISO, требований ОС, прошивки и устройств QEMU. Система не включает ISO или лицензии гостевых ОС. Полная установка каждого перечисленного дистрибутива пока не проверена.

| Основная ОС (хост) | Ускорение | Гостевая Windows 11 | Раздельные политики интернет/LAN |
|---|---|---|---|
| Linux x86-64 | KVM или TCG | UEFI + swtpm 2.0 | systemd/cgroup v2 + BPF, с авторизацией polkit |
| Windows 10/11 x64 | WHPX или TCG | **Не поддерживается в 0.1: нет Windows TPM-бэкенда** | **Не поддерживаются в 0.1**; доступны off/isolated/NAT |

KVM — компонент ядра Linux, его нельзя включить в Windows установкой EXE. Для WHPX нужны VT-x/AMD-V в UEFI и компонент Windows Hypervisor Platform. ВМ не использует автоматический тихий откат с ошибочного KVM/WHPX на TCG: ошибка показывается пользователю. `auto` выбирает TCG на Linux только при отсутствии доступа к `/dev/kvm`; фактический ускоритель выводится в CLI.

### Windows 11 на Linux-хосте

Выберите профиль Windows 11: ≥ 4096 МБ RAM, ≥ 2 CPU, диск ≥ 64 ГБ, UEFI и TPM 2.0. Установите `ovmf` и `swtpm`. Для Secure Boot нужна прошивка CODE/VARS с ключами Microsoft, например `OVMF_CODE_4M.secboot.fd` + `OVMF_VARS_4M.ms.fd`; можно указать пару вручную. Проверки требований установщика не отключаются. Состояние UEFI и TPM сохраняется на диске и включается в снимки; изменение аппаратной конфигурации может вызвать запрос ключа восстановления BitLocker.

## Сетевые режимы

По умолчанию **сетевой адаптер отсутствует**. Модель по умолчанию — `e1000`; доступны `rtl8139` и `virtio-net-pci` (VirtIO может требовать драйверов).

| Режим CLI | Интернет | LAN | Описание |
|---|---|---|---|
| `off` | Нет | Нет | Нет NIC |
| `isolated` | Нет | Нет | NIC с QEMU user network `restrict=on`, без пробросов портов; не соединяет разные ВМ |
| `nat` | Да | Да | User-mode NAT; **NAT не является запретом LAN** |
| `internet` | Да | Нет | Linux: deny локальных CIDR через BPF; публичный DNS |
| `lan` | Нет | Да | Linux: deny-all/allow локальных CIDR через BPF; всё ещё user-mode NAT |
| `tap` | По сети хоста | По сети хоста | Linux: заранее настроенный TAP, принадлежащий пользователю и включённый в мост |

`internet`/`lan` фильтруют соединения процесса QEMU, а не доверяют настройкам гостевой ОС. Для этих режимов QEMU запускается как **обычный пользователь** в отдельном systemd-сервисе с выключенным виртуальным CPU (`-S`). Привилегии запрашиваются только через polkit для systemd/BPF. До команды `cont` подтверждаются **оба** BPF-фильтра, ingress и egress; при отсутствии фильтров запуск отменяется. Правила основной ОС не отключаются и глобальный firewall не переписывается.

Локальные CIDR включают частные, loopback/link-local/multicast адреса и подсети интерфейсов хоста. Дополнительные маршрутизируемые корпоративные сети задайте через `--lan-cidr`. Публичные адреса корпоративной сети без этого не распознаются как LAN. Чтобы избежать исключений для локального DNS в режиме `internet`, сервис получает отдельный `resolv.conf` с указанным публичным `--dns` (по умолчанию 1.1.1.1). IPv6 user network отключён. Политика фиксируется при старте: после смены сети/VPN/маршрутов хоста перезапустите ВМ. Это IP-фильтрация, а не защита от внешнего VPN/прокси или DNS-туннелей гостя.

Для `lan` доступны исходящие соединения в разрешённые подсети, но нет L2-обнаружения и входящих LAN-соединений. Для полноценного присутствия в LAN используйте `tap`; мост/DHCP/firewall настраивает администратор хоста. Вариант с доступом к интернету через внешний LAN-прокси не блокируется IP-политикой. Не используйте NAT/мост для тестирования недоверенного ПО, которому не нужен внешний доступ.

## Установка

Сборки находятся в артефактах [GitHub Actions](https://github.com/Serge-Nook/multilayer/actions). Их нужно скачать и распаковать. Workflow собирает пакеты на push/PR и вручную; публикация релиза не выполняется автоматически.

### Arch Linux — AppImage

Установите зависимости хоста:

```sh
sudo pacman -S qemu-desktop qemu-img edk2-ovmf swtpm
# Для отдельных политик сети:
sudo pacman -S bpf polkit iproute2
chmod +x Multilayer-0.1.0-x86_64.AppImage
./Multilayer-0.1.0-x86_64.AppImage
```

Первый запуск показывает **«Установить/обновить — Удалить — Выйти»**. Установка без root копирует AppImage в `~/.local/opt/multilayer` и добавляет пункт меню. Для обновления скачайте новый AppImage и выберите установку/обновление. Для запуска без меню: `./Multilayer-0.1.0-x86_64.AppImage --gui`. При отсутствии FUSE: `--appimage-extract-and-run --gui`. AppImage содержит приложение/Qt, **не содержит ядро KVM, QEMU, OVMF или swtpm**.

### Debian 12+ / Ubuntu 22.04+ — DEB

```sh
sudo apt install ./multilayer_0.1.0_amd64.deb
multilayer --gui
multilayer --maintenance
```

DEB открывается системным менеджером пакетов, не исполняется как EXE. Меню обслуживания доступно после установки через приложение. Для обновления установите новый скачанный DEB; кнопка обновления через apt использует только настроенные репозитории (свой apt-репозиторий не включён). Для TPM: `sudo apt install ovmf swtpm`. Для BPF-политик установите пакет `bpftool` вашей ОС. В Ubuntu 22.04 bpftool поставляется в `linux-tools-*`; убедитесь, что `bpftool version` действительно работает, а не только существует обёртка в PATH.

Для KVM проверьте доступ к `/dev/kvm` и членство в группе `kvm` (после изменения группы нужен новый вход). Не запускайте весь GUI от root. Готовые Linux-сборки требуют glibc ≥ 2.35.

### Windows 10/11 — EXE

Запустите `Multilayer-0.1.0-Setup.exe`, выберите **«Установить/обновить — Удалить — Выйти»**. Приложение устанавливается для текущего пользователя, без удаления данных ВМ. GUI: ярлык «Мультислой». CLI: `%LOCALAPPDATA%\Programs\Multilayer\cli\multilayer-cli.exe`.

Отдельно установите [QEMU для Windows](https://www.qemu.org/download/#windows) (обычно `C:\Program Files\qemu`) и включите Windows Hypervisor Platform средствами Windows. QEMU с SDL нужен для консоли; headless-запуск работает без SDL. Установщик не скачивает исполняемые файлы и не включает системные компоненты без согласия пользователя. Для UEFI укажите совместимую пару CODE/VARS вручную, если пакет QEMU не содержит OVMF. Ограничения TPM и сети см. в таблице выше. Нативное WHPX/GUI-тестирование требует Windows-машины; успешная сборка EXE сама по себе не доказывает запуск ВМ.

## CLI

```sh
multilayer doctor
multilayer create --name 'Debian test' --guest Debian --iso /path/debian.iso \
  --memory 4096 --cpus 2 --disk 32 --network off --shared-folder /path/exchange
multilayer list
multilayer start UUID                      # отдельное окно консоли QEMU
multilayer start UUID --headless
multilayer pause UUID
multilayer resume UUID
multilayer link UUID down                  # отключить виртуальный кабель
multilayer link UUID up
multilayer shutdown UUID                   # ACPI, зависит от гостевой ОС
multilayer stop UUID --yes                 # немедленно, риск потери данных
multilayer edit UUID --network internet --dns 1.1.1.1 --lan-cidr 203.0.113.0/24
multilayer edit UUID --boot disk --iso ''   # убрать установочный ISO
multilayer clone UUID --name 'Debian copy'
multilayer snapshot UUID create before-test
multilayer snapshot UUID list
multilayer snapshot UUID restore before-test --yes
multilayer snapshot UUID delete before-test --yes
multilayer delete UUID --yes               # удаляет ВМ и все её данные
```

CLI возвращает JSON, ошибки — stderr и ненулевой код. Флаги глобального уровня (`--home`, `--gui`, `--maintenance`) идут перед командой. Пустой ISO допустим для загрузки с диска. Деструктивные действия требуют `--yes` или подтверждения GUI. Настройки/клонирование/снимки/удаление разрешены только при полностью выключенной ВМ; блокировки защищают от одновременных операций GUI/CLI.

Данные: Linux — `$XDG_DATA_HOME/multilayer` или `~/.local/share/multilayer`; Windows — `%LOCALAPPDATA%\Multilayer\data`. Можно задать `MULTILAYER_HOME` или `--home`. Не используйте сетевые файловые системы с ненадёжными блокировками. Для Unix-сокета QMP полный путь должен быть не длиннее 100 байт; для фильтра сети путь данных не должен содержать пробелы/двоеточия. Журналы QEMU, последовательного порта и TPM находятся в каталоге ВМ. На Linux QMP защищён каталогом 0700; Windows использует локальный named pipe, а не неаутентифицированный TCP-порт. Данные ВМ могут содержать чувствительную информацию — ограничивайте права к каталогу данных, особенно при явном выборе `--home`.

## Разработка и проверка

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[dev]'
ruff check .
ruff format --check .
mypy multilayer
python -m unittest discover -s tests -v
MULTILAYER_INTEGRATION=1 python -m unittest discover -s tests -v
python -m multilayer --gui
```

Интеграционные тесты используют QEMU/TCG, реальное QMP-управление, загрузку минимального bootable ISO, снимки с проверкой байтов диска, клонирование, UEFI/TPM и подключение диска обмена. Не требуют скачивания ОС, root или `/dev/kvm`. Они **не заменяют** установку гостевых ОС и проверку firewall на реальной системе.

Сборка Linux: `bash packaging/build_linux.sh`; нужны `dpkg-deb`, `desktop-file-utils` и библиотеки Qt/XCB (список в Linux job CI). Для AppImage задайте `APPIMAGETOOL=/path/appimagetool-x86_64.AppImage` (официальный appimagetool 1.9.0). Сборка Windows на Windows с Inno Setup 6: `./packaging/build_windows.ps1`. Оба скрипта используют PyInstaller, GUI не нужен во время сборки.

Готовые пакеты: [GitHub Releases](https://github.com/Serge-Nook/multilayer/releases). Тег `v<версия>` запускает проверки и сборки, затем публикует предварительный релиз с тремя установщиками и `SHA256SUMS`. Опубликованные релизы не перезаписываются; версия тега должна совпадать с версией приложения. Публикация выполняется только после успешной сборки обеих платформ.
